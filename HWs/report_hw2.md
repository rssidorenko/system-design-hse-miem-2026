# Проектирование электронной системы для учеников, родителей и преподавателей начальной школы
## Модули и интеграции
В качестве подхода к разработке модели ПО применяем **Domain Driven Design**, так как при проектированиии такой системы крайне важно следование бизнес-логике (система должна быть интуитивно понятной и удобной в использовании). Для реализации сложной SaaS-системы, которая позволит объединять изолированные друг от друга школы, следует также рассмотреть микросервисный подход к проектированию архитектуры.

### Описание модулей
1. **Сервис авторизации и аутентификации**  
  Необходим для регистрации и входа пользователей в приложение. Следует отметить, что сервис должен быть stateful, чтобы пользователям не приходилось каждый раз при входе в приложение заново регистрироваться.
2. **Сервис управления профилями пользователей**  
   Требуется для создания, изменения и удаления профилей пользователей, актуализации данных в них, назначения и изменения ролей, предоставления прав доступа. Кроме того, при помощи сервиса возможно отслеживание действий пользователей, что необходимо для логирования и обнаружения ошибок.
3. **Сервис для внесения данных пользователями**  
   Будет применяться для добавления информации преподавателями (посещаемость, оценки, задания) и родителями (информация об отсутствии учеников).
4. **Сервис для обмена сообщениями и файлами**  
   Необходим для функционирования чата для преподавателей и родителей.
5. **Сервис для хранения документов и изображений**  
   Будет использоваться для сохранения не текстовых данных в приложении.
6. **Сервис для формирования и выгрузки отчётов**  
   Требуется для поддержания работоспособности функционала по выгрузке Excel-отчётов из приложения.
7. **Сервис для интеграции отдельных образовательных учреждений**  
   При помощи сервиса будет осуществляться контроль по соблюдению требований к изолированности отдельных элементов системы (школ).
